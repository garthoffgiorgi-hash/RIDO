# Landing pages — v1 (2026-08-07)

**Bundle:** `2026-08-07-landing-pages-v1/` · **Surface:** rider landing (`/`), driver landing
(`/drivers`), about (`/about`) · **Status:** reference for building the real pages. Supersedes
`2026-08-05-landing-v1.dc.html` (the old single-page site these three pages replace).

## What it is

A design handoff, not a single export: three plain-text `.dc.html` pages, a shared `_ds/`
design-system folder (tokens + components), and a `support.js` preview runtime. Read
`brand/exports/2026-08-07-landing-pages-v1/README.md` (the bundle's own note) first — it's
unusually good: page-by-page section breakdowns, prop names, icon library (Lucide,
`data-lucide` attributes), interaction states. This note only covers what that one doesn't: where
it disagrees with the rest of this repo.

**`_ds/` and `support.js` are preview-only.** They let the `.dc.html` files render in a browser.
Neither ships in the real app — don't import `_ds_bundle.js`, don't link `_ds/styles.css`.

## ⚠️ The Rider page carries a stale figure — verified, not assumed

`RIDO Rider.dc.html` reuses two numbers **verbatim** from the old single-page export
(`2026-08-05-landing-v1.dc.html`), the same ones `2026-08-05-landing-v1.md` already documented as
wrong:

| Location | Text | Fix |
|---|---|---|
| Hero stat tile (~line 57) | "Drivers keep **87%** of the average fare" | Use `docs/business/monetization.md`'s **~86%** commission-only figure — cite it, don't retype a number |
| Floating ride card (~line 98) | "**$7.30** kept (**87%**)" on an implied $8.40 fare, "An incumbent at 30% would hand them $5.88" | Drop this specific per-ride example. No tier maps to 87% per-ride (tiers imply 80% / 88% / 92% depending on the driver's month-to-date position) — same finding as the original audit, carried forward unfixed |

**This bundle's own README says "Fidelity: High-fidelity. Colors, type, spacing, and copy are
final."** Don't let that framing override the correction above — the design system's own readme,
inside the `_ds/` folder alongside these pages, was generated by reading this repo, but notes
that `apps/web`'s `src/` "does not exist yet," meaning it was built from a repo snapshot
**before** the `docs/business/monetization.md` fix landed. This isn't Design ignoring the repo;
it read a real, now-outdated snapshot.

**The Driver and About pages don't have this problem — verified, not assumed:**
- `RIDO Driver.dc.html`'s economics section is **props-driven** (`monthlyFares`,
  `incumbentTakePct`), computing from the correct 20%/12%/8% tiers live rather than a baked-in
  blended percentage. Nothing to fix.
- `RIDO About.dc.html`'s commission-tiers section uses the **exact** $3,600 GMV worked example
  from `docs/business/monetization.md` — $488 commission, $3,112 kept, 13.6% blended. Matches to
  the dollar. Build from it as-is.

## Design tokens: this bundle has more precision than the app currently does

`_ds/.../tokens/*.css` is a fuller token set than what's mapped into
`apps/web/src/app/globals.css` today — Signal/Midnight alpha tints (chip backgrounds, focus
ring), concrete success/danger hex values (`#2E8B6F` / `#C2453B` — the app previously only had
"a desaturated green" / "a warm red" with no hex), a full type scale (display-xl through
eyebrow), shadow tokens, and motion easing/duration tokens. The base 7 colors and both font
families match the app's `@theme` block exactly — no conflict there, just a gap in what's already
committed. Reconciled into `globals.css` in the same change that added this bundle; check that
file's `@theme` block for the current set before hand-writing a value here.

## Build notes

- Icons: [Lucide](https://lucide.dev), 2px stroke, `currentColor`. Swap the bundle's CDN
  (`unpkg.com/lucide`) for `lucide-react` in the real app, keeping the same icon names from each
  page's `data-lucide` attributes.
- Driver page testimonials are explicitly labelled illustrative, not verbatim reviews — keep that
  framing or drop them; don't present them as real quotes.
- `pilotMonths` (About page, default 6) and the driver economics props are the only dynamic
  inputs — everything else is static markup per-page, matching a 3-route static site, not a
  component prop system to fully replicate.
